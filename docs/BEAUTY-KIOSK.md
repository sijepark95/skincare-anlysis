# AELUNE 통합 뷰티 키오스크

## 현재 흐름

`/kiosk`: 시작 → 연령대 → 동의 → 새 사진 → 팔레트·얼굴형·베이스 후보 확인 → 통합 결과. 피부 분석 화면으로 이동하거나 필수 설문을 작성할 필요가 없습니다. 결과는 피부·성분·스킨케어, 얼굴 특징·컬러, 메이크업3개, 헤어스타일3개·헤어 컬러3개, 저장·종료 순서입니다. 영어·한국어·스페인어를 바꿔도 선택과 결과는 유지하고 AI를 재호출하지 않습니다.

성인은 Gender를 선택하거나 응답하지 않을 수 있습니다. 사진으로 나이·Gender를 추정하지 않습니다. 13세 미만은 개인 사진 기능에서 제외하며, 청소년 사진은 기본적으로 비활성화했습니다. 사진 없이 확인한 스타일 선택으로 계속할 수도 있습니다. 피부 타입은 미상, 추가 고민과 제외 성분은 빈 값으로 시작하며 결과에서 선택적으로 수정합니다.

Man을 직접 선택하면 자연스러운 피부 표현·정돈된 눈썹·은은한 윤곽 메이크업과 텍스처드 크롭·커튼 파트·소프트 퀴프 헤어를 제안합니다. Woman은 기존 부드러운 메이크업·헤어 방향, 그 외/미응답은 열린 스타일 방향으로 유지합니다. 선택은 사진에서 추정하지 않습니다. 이미지 편집에만 세션 내 스타일 방향을 전달하고, 원래 Gender와 스타일 방향은 개별 DB/QR에 저장하지 않습니다. 이 스타일 방향은 피부/성분/제품 적격성이나 얼굴 자체를 바꾸는 기준이 아닙니다. 로컬 가이드는 현재 스타일 문구를 반영할 수 있고, QR은 저장된 일반 팔레트·확정 스타일 선택을 유지합니다.

공개 홈페이지의 승인된 전체 화면 영상은 그대로 유지합니다. 기존 `/kiosk/skin`, 피부·컬러·뷰티 API와 이전 QR도 유지합니다.

## 로컬 실행과 설정

프로젝트 폴더에서 실행합니다. 이미 실행 중이면 두 번째 서버를 띄우지 않습니다.

```powershell
npm.cmd run dev:connected
```

앱은 `http://127.0.0.1:3000/kiosk`, 관리자는 `/management`입니다. 새 기기는 관리자 Devices에서 코드를 만들고 `/kiosk/pair`에서 페어링합니다. 현재 로컬 Supabase와 제한된 분석 writer에 새 마이그레이션을 적용했습니다. 기존 매장·계정·카탈로그는 유지합니다.

비밀 값은 채팅이나 Git에 넣지 않습니다. 기존 무시된 `.env.local`의 다음 설정을 사용하며 변경 후 서버를 재시작합니다.

```dotenv
APP_MODE=supabase
ANALYSIS_PROVIDER=openai
ANALYSIS_SERVICE_URL=http://127.0.0.1:8000
ANALYSIS_API_KEY=<동일한 서버 전용 비밀 값, 32자 이상>
OPENAI_API_KEY=<서버 전용 OpenAI 키>
ANALYSIS_DATABASE_URL=<제한된 writer 연결>
ANALYSIS_BEAUTY_PREVIEW_ENABLED=true
BEAUTY_TEEN_PHOTO_ENABLED=false
BEAUTY_PUBLIC_ORIGIN=
```

`ANALYSIS_BEAUTY_PREVIEW_ENABLED`는 Next와 FastAPI 양쪽에 필요합니다. 연결 실행기와 OpenAI Compose override가 전달합니다. 이전 `ANALYSIS_BEAUTY_MAKEUP_ENABLED`는 기존3개 생성 경로용이며 새9개 경로의 플래그를 대신하지 않습니다. 키가 없어도 사진 없는 스타일 가이드는 동작하고, 외부 요청 실패를 가짜 결과로 대체하지 않습니다.

청소년 사진을 운영 검토 없이 활성화하지 않습니다. 추후 승인된 운영자가 앱의 `BEAUTY_TEEN_PHOTO_ENABLED`와 DB의 `private.beauty_release_settings.teen_photo_enabled`를 모두 활성화해야 합니다. 한쪽만 켜면 서버가 거부합니다.

## 한 사진의 분석·추천

1. 버전별 목적 동의를 저장한 후 카메라가 자동으로 열립니다. 로컬 위치 안내가 중앙의 안정된 한 얼굴을 확인하면 취소 가능한3초 뒤 촬영·분석합니다. 업로드는 직접 분석을 누릅니다. 사진을 선택하기 전에 외부 전송 동의가 필요합니다.
2. BFF가 페어링·소유 세션·연령·동의·크기를 확인하고 DB에서 단 한 번의 시도를 원자적으로 확보합니다. 새 `/v1/analyze/beauty-complete`가 메타데이터를 제거한 사진과 불투명 UUID를 받아 한 번의 OpenAI Responses 요청으로 피부와 스타일을 함께 관찰합니다. 고정 모델은 `gpt-4.1-mini-2025-04-14`, 계약은 `beauty-complete-v1`입니다. `store:false`, 도구·대화 이력·재시도 없음이 적용됩니다.
3. 피부와 스타일의 사진 품질을 독립적으로 판단합니다. 모공·잡티·잔주름·홍조·각질 중 불명확한 것은 판단 불가입니다. usable사진의 모공→피부결, 잡티→균일한 톤, 잔주름→잔주름 관리만 매장의 검토된 성분 정책에 연결합니다. 홍조·각질로 민감도나 수분 상태를 추정하지 않습니다.
4. 별도 사진 전용 추천 입력이 실제 관찰과 사용자가 선택한 정보만 전달합니다. 설문 답변을 꾸며내지 않습니다. 추천 이유는 고정된 관찰·목표·성분·제품 사실로 구성하며, LLM이 제품이나 효능을 추가하지 않습니다. 관련 성분/제품이 없으면 그 상태를 그대로 표시합니다.
5. 팔레트·얼굴형·베이스 밝기/언더톤은 제안 후 손님이 확인합니다. 베이스는 가까운 매장 비교 후보이며 정확한 호수 일치를 보장하지 않습니다. 컨실러는 피부톤 맞춤이 기본이고 밝힘은 손님이 선택한 경우만 적용합니다.

눈·코·입술 퍼센트는 브라우저의 로컬 FaceLandmarker가 계산한2D 비율입니다. 눈 세로/가로, 코 너비/얼굴 너비, 입술 높이/입 너비를 나타내며 정확도·매력·질환 점수가 아닙니다. 각도·감김·가림 등 품질 기준을 통과하지 못하면 숫자를 숨깁니다. 얼굴 랜드마크와 비율은 서버로 보내지 않습니다. 동물상은 선택된 여섯 외형적 분위기 중 하나로 재미만을 위한 제안이며 불명확하면 생략합니다. 모델 파일의 출처·해시는 BEAUTY-ASSETS.md에 있습니다.

결과의 얼굴 영역은 참고 화면처럼 내 사진 옆에 세 가지 비율 막대와 특징 이름을 배치합니다. 동물상·확인한 얼굴형은 해시태그로 묶으며, 사진 위 윤곽선은 장식입니다. 막대는 0–100 범위의 실제 기하 비율을 그대로 표시하고, 강아지/고양이 확률이나 점수로 바꾸지 않습니다. 컬러 카드는 확인한 팔레트의 네 색·색감과 선택한 베이스 언더톤·밝기를 정리합니다. 베이스를 선택하지 않았다면 미확인으로 남기며 팔레트로 대신 채우지 않습니다. 피부·눈동자·입술 색의 측정 수치는 현재 제공하지 않습니다. 메이크업·헤어·헤어 컬러는 세 장씩 비교하는 스타일북이며, 실제 생성 이미지마다 짧은 설명을 붙입니다. 화면을 읽거나 언어를 바꾸는 동작은 새 AI 요청을 만들지 않습니다.

## 원본 기반 이미지9개

별도 `2026-10-beauty-preview-v1` 동의는 처음에 체크하지 않습니다. 동의와 분석·확인이 모두 완료되면 메이크업3개 → 헤어스타일3개 → 헤어 컬러3개를 차례로 생성합니다. 각각 동일한 원본에서 시작하고 다른 생성 이미지를 재입력하지 않습니다. 고정 이미지 모델/프롬프트는 서비스 README와 프로토콜에 기록되어 있습니다.

각 카드의 완료 즉시 이미지를 표시하고 실패는 해당 카드에 남깁니다. 한 슬롯에 한 번만 요청하고 자동 재시도하지 않습니다. 상단에는 현재 작업·실제 완료 개수를 보여주며 결과를 계속 읽을 수 있습니다. 가짜 진행률과 예상 시간을 표시하지 않습니다. 각 제공자 요청은 최대60초, 사설 HTTP는75초, 전체는12분과 세션 시작15분 중 먼저 도달하는 시점에 종료합니다.

방향 변경, 동의 철회, 화면 숨김·이탈, 종료·만료 시 남은 작업을 중단하고 원본·결과 URL을 폐기합니다. 늦게 도착한 결과는 저장/표시하지 않습니다. 이미 제공자가 시작한 요청과 요금의 취소를 보장하지 않습니다. 이미지 API에는 Responses의 `store:false`가 없으므로 동의에 제공자 처리/보관 가능성을 안내합니다. 결과는 AI 예시이며 얼굴 보존이나 실제 화장·염색 결과를 보장하지 않습니다.

## 관리자와 정규화된 카탈로그

관리자는 실제 제품과 완전한 전성분을 검토·공개하고 매장 재고·표시를 활성화합니다. 스킨케어는 매장이 검토한 목표→성분 정책을 사용합니다. 립·블러셔·아이섀도·파운데이션·컨실러는 새 색상 검토 화면에서 필요한 정보를 작성해야 합니다.

공통 불변 색상 버전과 색조/베이스 상세를 분리합니다. 색상·언더톤·밝기·마무리를 검토하고 베이스에는 커버력을 지정합니다. 미완성 정보는 초안으로 남습니다. 제품 정체성·전성분 배합 버전·색상 버전·매장 재고는 별도 관계이며 테넌트 FK/RLS를 유지합니다. 같은 매장의 공개·재고 보유·알려진 완전한 배합·검토된 색상 제품만 추천합니다. 제외 성분과 잘못된 카테고리 조합을 차단합니다. 제품이 없으면 다른 매장이나 생성 상품으로 채우지 않습니다.

성인 통계는 별도 동의한 완료 세션만 한 번 집계합니다. Gender는 개별 행으로 저장하지 않고 Finish 시 집계에만 사용합니다. 청소년은 제외합니다. 최근 완료된4주 UTC고정 기간의 연령대/Gender 분포를 각각 보여주며, 어떤 비영(非零) 집단이10명 미만이면 해당 분포 전체를 숨깁니다. 개인 결과를 관리자에게 공개하지 않습니다.

## 저장·QR·개인정보

로컬 Download guide는 확인한 스타일·등록 제품을 포함한 독립 HTML이며 현재 언어를 사용합니다. 사진·생성 이미지·얼굴 비율·동물상·Gender·원본 AI 관찰은 제외합니다. 외부 리소스나 스크립트 없이 읽고 인쇄할 수 있습니다. 생성 이미지를 개별 다운로드하면 그 파일은 사용자의 기기에 남으며 사용자가 관리합니다.

QR은 별도 저장 동의와 공개 HTTPS가 필요합니다. 현재 `BEAUTY_PUBLIC_ORIGIN`은 빈 값이므로 발급을 비활성화합니다. `127.0.0.1`은 폰에서 개발 PC에 연결되지 않습니다. 터널/공개 배포는 자동으로 하지 않습니다.

`beauty-complete-guide-v1`에는 확정된 선택·locale·원래 적격 제품의 배합/색상 버전만 저장합니다. 최대18개 제품,7일 보관, 세션당1개입니다.256비트 토큰은 URL fragment에만 두고 DB에는 SHA-256 해시만 저장합니다. 폰은 fragment를 즉시 지운 뒤 같은 출처 POST로 읽습니다. 익명 publishable-key capability RPC를 사용하고 로그인·service role·테이블 공개 SELECT가 없습니다. 기존 QR도 계속 읽기/철회할 수 있습니다.

Finish는 키오스크의 일시 정보를 지우되 별도 동의한 QR을 유지합니다. 링크를 가진 사람은 열거나 삭제할 수 있습니다. 배합·색상 버전·표시·재고가 바뀌면 원래 제품을 사용 불가로 표시하고 대체하지 않습니다.7일 만료 즉시 읽기를 차단하고 매분 정리 작업이 삭제합니다. 다운로드/인쇄본은 서버에서 회수할 수 없습니다.

## 공개 배포 준비

현재 로컬 구현만 완료하며 공개 도메인/클라우드 구매·배포는 하지 않았습니다.

1. HTTPS 앱 주소, Hosted Supabase, 비공개 FastAPI를 준비합니다. SUPABASE-SETUP.md대로 마이그레이션·정확히9개 제한된 writer 권한·Auth hook·SMTP·익명 기기 인증·매분 cleanup을 설정합니다. 기존 DB를 reset하지 않습니다.
2. 배포 환경의 `NEXT_PUBLIC_APP_URL`과 `BEAUTY_PUBLIC_ORIGIN`을 실제 같은 HTTPS origin으로 설정합니다. Supabase 공개 URL/key는 빌드 전에, 비밀 키/DB URL은 서버에만 설정합니다. Supabase Site URL/redirect allowlist도 같은 운영 주소로 맞춥니다. FastAPI에는 OpenAI키/분석키만 전달하며 SMTP/DB관리자키를 전달하지 않습니다.
3. Node22이상에서 `npm ci`, `npm run check`, `npm run build`, `npm run start`를 사용합니다. 개발 서버는 운영에 사용하지 않습니다. TLS reverse proxy는 개별 생성 요청 제한보다 긴 시간을 허용하고 BFF↔FastAPI 연결을 비공개로 유지합니다. 공유 환경에는 분산 사용량 제한/경보/백업·복구가 필요합니다.
4. 실제 매장 카탈로그와 성분 정책/색상을 검토하고 운영 주소에서 기기를 새로 페어링합니다. 개발 쿠키는 이동하지 않습니다.
5. 동의받은 성인 평가 사진으로 조명별 관찰, 베이스 후보, 얼굴 보존, 대기 시간을 확인합니다. 실제 태블릿의 자동 촬영·취소·초기화, 다른 네트워크 폰 QR·삭제·만료를 검증한 뒤 제한된 파일럿을 진행합니다. 현재 테스트는 임상/색상 정확도를 입증하지 않습니다.

## 테스트와 토큰 절약

현재 통과 수치는 STATUS.md/VERIFICATION.md를 봅니다. 합성 BFF 검증은 `node scripts/beauty-complete-acceptance.mjs --local-synthetic`이며 실제 외부 AI/이메일 요청을 하지 않습니다. Gmail이 연결되어 있으므로 계정/메일을 만드는 `scripts/supabase-smoke.mjs`는 실행하지 않습니다.

작은 작업은 `npm run context -- beauty`로 현재 결정과 변경 경계만 읽습니다. 관련 도메인/응용/HTTP/DB/UI 테스트부터 실행하고 변경 없는 전체 학습 데이터·대화·미디어는 다시 읽지 않습니다. STATUS는 짧게 덮어쓰고 증거는 VERIFICATION에 둡니다. 번역·추천·설명은 검증된 규칙을 재사용하며 언어 변경·수동 선택·결과 읽기에는 AI를 호출하지 않습니다.
