# OpenAI 피부 사진 분석 사용 안내

현재 키오스크는 사용자 요청에 따라 **OpenAI가 사진을 직접 관찰하는 모드**를 사용합니다. ChatGPT 소비자 앱의 대화창을 연결하는 방식이 아니라, 비공개 서버에서 OpenAI Responses API의 `gpt-4.1-mini-2025-04-14`를 호출합니다. 이 모드에서는 ConvNeXt, 기존 성분 후보 모델, 학습 데이터 또는 체크포인트를 불러오지 않습니다. 기존 실험 모델과 독립 비교 도구는 보존되어 있으며, OpenAI의 정확도가 더 높다고 검증한 결과는 아닙니다. [고정 모델 안내](https://developers.openai.com/api/docs/models/gpt-4.1-mini)

## 키오스크에서 사용하기

1. [키오스크](http://127.0.0.1:3000/kiosk)를 열고 새 세션을 시작합니다. 기존 결과 화면은 **Finish & clear session**으로 정리하세요. 새 동의 안내는 `2026-10-openai-v1`입니다.
2. 임시 세션 동의와 별도로 **Analyze my photo with OpenAI (optional)**를 선택합니다. 기본값은 꺼져 있습니다. 성인이며 사진에 본인 한 명만 있다는 확인, 외부 사진 처리와 보관 안내를 포함합니다. 사진 동의 버전은 `2026-10-openai-photo-v1`입니다.
3. 사진 동의를 선택하지 않으면 카메라와 파일 선택을 열지 않습니다. 설문 선택 후 **See my store matches**로 매장 정책 기반 추천을 확인할 수 있습니다. OpenAI 사진 요청은 발생하지 않습니다.
4. 사진 동의 후 사진 단계로 이동하면 카메라가 자동으로 켜집니다. 한 명의 얼굴이 중앙에 안정적으로 잡히면 **3초 카운트다운 → 자동 촬영 → 사진 분석**으로 진행합니다. 얼굴이 벗어나거나 화면을 떠나면 취소합니다. **Pause camera**, **Choose a photo**, **Continue without a photo**도 사용할 수 있습니다.
5. 결과 상단의 **Your skin consultation**에서 사진 관찰 요약과 관리 목표를 확인합니다. **Explore your five photo observations**를 열면 다섯 항목의 의미와 추천에 사용되는 범위를 자세히 볼 수 있습니다. 그 아래의 **Ingredients with a purpose.**에는 성분의 화장품 기능·추천 근거·실제 매장 제품 매칭 여부가 표시되고, 제품 카드에는 등록된 제품의 전성분 매칭 근거가 나옵니다. 매장 추천 제품이 없어도 요약과 성분 가이드는 표시됩니다. 사진 관찰 자체는 OpenAI가 수행하며, 화면의 상담 문장은 저장된 관찰·설문·매장 가이드에서 생성하는 고정된 해석입니다. 이를 위한 두 번째 LLM 호출이나 추가 외부 전송은 없습니다.
6. **Finish & clear session**으로 임시 결과를 정리합니다. 90초 무활동 시 안내하고 120초에 초기화합니다. 서버의 방치 세션은 15분 후 만료되며 예약 정리 작업이 삭제합니다.

## 관찰 항목과 추천의 관계

| 관찰 항목     | 표시 의미                        | 제품 매칭에 추가할 수 있는 목표                         |
| ------------- | -------------------------------- | ------------------------------------------------------- |
| Redness       | 사진에서 보이는 붉은 외관        | 추가하지 않음; 민감성으로 추정하지 않음                 |
| Visible spots | 사진에서 보이는 얼룩 형태의 외관 | 사용 가능한 사진에서 명확히 보일 때만 even-looking tone |
| Pores         | 사진에서 보이는 모공 외관        | 사용 가능한 사진에서 명확히 보일 때만 texture           |
| Fine lines    | 사진에서 보이는 잔주름 외관      | 사용 가능한 사진에서 명확히 보일 때만 fine lines        |
| Flaking       | 사진에서 보이는 각질 들뜸 외관   | 추가하지 않음; 수분 부족으로 추정하지 않음              |

각 항목은 `visible`, `not_visible`, `uncertain`, `not_assessable` 중 하나입니다. `not_visible`은 이 사진에서 보이지 않는다는 뜻이며 실제로 없다는 보장이 아닙니다. 진단, 중증도, 신뢰도 퍼센트, 수분 수치 또는 피부 장벽 측정값을 만들지 않습니다.

사진 품질이 `usable`이고 항목이 `visible`인 경우에만 위의 제한된 목표를 손님이 선택한 목표와 합칩니다. 이는 화장품 탐색을 위한 매장 정책 연결이며 해당 성분이 필요하거나 효과가 있다는 검증이 아닙니다. `limited` 또는 `not_assessable` 사진의 관찰은 추천 목표를 추가하지 않습니다. 조명·흐림·가림·화장/필터·해상도 제한은 함께 표시합니다. 사진 없는 결과도 설문과 정책으로 진행합니다.

실제 제품 추천은 서버의 **검토된 조직 성분 정책 → 정규 INCI → 해당 매장의 게시된 완전한 전성분 제품** 순서로 결정합니다. 매장 재고, 표시 여부, 선택한 피부 타입과 제외 성분 조건을 계속 적용합니다. OpenAI가 제품이나 성분을 직접 선정하거나 안전성·함량·효능을 보장하지 않습니다. 적합한 제품이 없으면 직원에게 문의하라는 빈 결과가 정상입니다. 초기 온보딩 예시 정책은 실제 운영 전에 검토해야 합니다.

## 실패·재시도·사진 없는 계속

사진 API 시도는 **세션당 최대 한 번**입니다. 요청 직전에 DB에 원자적으로 기록하므로 동시 요청이나 서버 재시작도 두 번째 전송을 만들지 않습니다. 성공한 결과는 다시 불러오고, 시간 초과·거절·통신 오류·결과 검증 실패를 자동으로 재시도하지 않습니다. 모델을 ConvNeXt 또는 mock으로 몰래 바꾸지 않습니다.

실패한 세션에서는 다시 Analyze/Retake/Choose를 반복하지 못하도록 막습니다. **Continue without a photo**로 설문 기반 결과를 만들거나 **End session** 후 새 세션에서 다시 동의하고 촬영하세요. 사진 없는 계속은 새로운 외부 사진 요청을 만들지 않습니다. 이전 시도의 사진이 이미 OpenAI에 전달되었을 수 있으며, 사진 없는 계속/세션 종료가 그 전송을 되돌리지는 않습니다. 늦게 도착한 결과는 사진 없는 완료 결과나 종료된 세션을 복구하지 못합니다.

## 서버 설정

이 PC에는 기존 서버용 API 키와 비공개 Python 환경이 준비되어 있습니다. 비밀번호/키를 채팅이나 명령 인수에 입력하지 마세요. `.env.local`을 덮어쓰지 말고 필요한 설정만 비공개로 편집합니다.

```dotenv
ANALYSIS_PROVIDER=openai
ANALYSIS_SERVICE_URL=http://127.0.0.1:8000
ANALYSIS_API_KEY=<웹과 비공개 분석 서비스에 동일한 연결용 비밀 키>
OPENAI_API_KEY=<서버 전용 OpenAI API 키>
ANALYSIS_OPENAI_TIMEOUT_SECONDS=30
EXPLANATION_PROVIDER=disabled
```

`OPENAI_API_KEY`에 `NEXT_PUBLIC_` 접두사를 붙이지 마세요. 이 키는 서버에서만 사용하고 사진 분석을 수행하는 비공개 Python 서비스에 명시적으로 전달하며 브라우저 번들에는 포함되지 않습니다. 사진 분석 모델과 프롬프트는 코드에서 고정합니다. 최대 제공자 대기 시간은 30초입니다. 키 형식이 올바르다는 것은 계정 사용 한도/결제/모델 권한을 보장하지 않습니다.

현재 실행기는 `.local/ml-workspace.json`의 비공개 가상환경을 재사용할 수 있지만, OpenAI 모드에는 **PyTorch, GPU, 데이터셋 또는 학습 가중치가 필요하지 않습니다.** 새 환경은 Python 3.12 환경에 `services/analysis/requirements.lock`의 API/Pillow 의존성만 설치하면 됩니다. 별도 환경은 `SENMIVA_PYTHON`에 실제 Python 실행 파일의 절대 경로를 지정합니다. 실행기는 API 소스와 의존성 없는 고정 vision 프로토콜을 함께 읽습니다. [Python 서비스 설치](../services/analysis/README.md)

아래는 프로젝트 폴더에서 실행합니다. 기존 서버가 같은 포트에서 실행 중이면 해당 실행 터미널에서 종료한 뒤 다시 시작하세요.

```powershell
Set-Location 'C:\Projects\AELUNE'
npm.cmd run supabase:migrate
npm.cmd run supabase:check
npm.cmd run dev:connected -- --check
npm.cmd run dev:connected
```

신규 마이그레이션 `202610110004`/`202610110005`를 적용해야 사진 동의, 시도 제한과 관찰 결과가 저장됩니다. 데이터베이스 초기화는 필요하지 않습니다. 설정 변경 후 실행 중인 서버를 다시 시작해야 합니다. 관리자 **Workspace settings**에서 OpenAI, 외부 사진 동의/보관과 정책 기반 추천 상태를 확인할 수 있습니다. 이전 로컬 모델 모드를 선택하려는 경우에만 [선택형 실험 모델 안내](KIOSK-MODEL-SETUP.md)를 사용하세요.

## 데이터 경로와 보관

`브라우저의 임시 사진 → 페어링·동의를 검증하는 Next API → 비공개 FastAPI → 메타데이터 없는 JPEG → OpenAI → 검증된 관찰 범주 → 매장 정책·상품 필터 → 키오스크` 순서입니다. 신원, 나이/성별 추정, 전체 설문, 조직/매장 식별자, 제품·성분 목록과 AI-Hub 학습 자료는 사진 API 입력에 포함하지 않습니다.

입력은 정지 JPEG/PNG/WebP, 최대 10MiB, 최소 224px씩, 최대 2,500만 디코딩 픽셀로 제한합니다. 서비스는 EXIF 방향을 적용하고 RGB 픽셀을 새 이미지로 재구성하여 EXIF/ICC/XMP/텍스트를 제거합니다. 외부 전송은 긴 변 1536px 이하, 최대 4MiB의 JPEG만 사용합니다. 파일이나 업로드 스토리지에 사진을 쓰지 않습니다. 실시간 촬영의 브라우저 캡처는 비율을 유지하며 긴 변 1920px 이하입니다.

DB에는 고정된 모델/프롬프트, 동의·시도 메타데이터, 다섯 특징 범주, 품질 제한과 제품 매칭 근거만 정규화하여 임시 보관합니다. 사진/원본 API 응답/요청 본문을 DB·로그·고객 이력·학습 데이터에 저장하지 않습니다. 종료·철회·기기 해제·만료 시 분석, 사진 동의/시도와 추천 하위 기록을 삭제합니다. 기존 최소 일반 동의/종료 세션 메타데이터와 익명 매장 일별 카운터는 기존 보관 정책을 따릅니다. 직원은 개별 사진, 설문이나 관찰 결과를 조회할 수 없습니다. [DB 계약](DATABASE.md)

OpenAI 요청의 `store:false`는 응답의 애플리케이션 상태 저장을 끄는 설정이며 **제공자의 모든 보관을 없앤다는 뜻이 아닙니다.** 기본 abuse-monitoring 로그는 문서상 예외를 포함하여 최대 30일 보관될 수 있습니다. API 입력/출력은 기본적으로 모델 학습에 사용되지 않지만, 계정의 명시적 데이터 공유 선택은 별도 확인해야 합니다. 이 앱의 메모리 처리·세션 삭제와 제공자의 보관은 다른 경계입니다. [OpenAI 데이터 제어](https://developers.openai.com/api/docs/guides/your-data)

## 확인한 범위와 남은 평가

합성된 비인물 이미지 한 장으로 실제 API의 `no_face/not_assessable`, 매장 빈 결과, DB 저장/동일 결과 재사용/삭제 경로를 확인했습니다. 사진 없는 흐름은 외부 시도가 없음을 확인했습니다. 이는 실제 얼굴의 피부 분석 정확도나 제품 적합성 검증이 아닙니다. 별도로 동의받은 독립 평가 사진, 다양한 조명/카메라/피부색 환경, 사람 평가 기준과 매장 정책 검토가 필요합니다. 기존 학습 자료를 새 외부 사진 동의 없이 전송하지 않습니다. [독립 비교 도구](VISION-COMPARISON.md)
