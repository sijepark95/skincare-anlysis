# 선택형 로컬 실험 모델 연결 안내

**현재 활성 키오스크는 사용자 요청에 따라 OpenAI 사진 분석을 사용합니다.** 현재 설정·동의·화면 흐름은 [OpenAI 피부 사진 분석 안내](OPENAI-SKIN-SETUP.md)를 먼저 읽으세요. 아래 문서는 `ANALYSIS_PROVIDER=experimental`을 명시적으로 선택할 때만 적용하는 기존 로컬 모델 경로를 보존한 것입니다. OpenAI 모드에서는 ConvNeXt/성분 모델, 학습 데이터 또는 코드 지원 파일을 불러오지 않습니다. OpenAI를 비교 평가의 우승 모델로 선정한 것은 아닙니다.

이 모드는 이 PC에 저장된 두 학습 결과를 불러오는 **실험용 로컬 연결**입니다. 피부/성분 추론은 재학습이나 외부 AI API 없이 실행하며, 별도 선택 동의가 있을 때만 OpenAI 매칭 설명을 추가합니다. ConvNeXt-Tiny의 8개 사진 코드를 확인된 원천 순서로 묶고, 성분 모델의 기존 학습에서 지원한 조합인 경우 설문과 함께 성분 후보 순위에 반영합니다. 의료 진단이나 검증된 피부 건강 점수를 제공하지 않습니다. 확인한 범위와 한계는 [원천 코드 입력 계약](ML-SOURCE-CODE-CONTRACT.md)에 있습니다.

## 로컬 experimental 모드를 선택한 경우

연결된 개발 서버가 켜져 있다면 [키오스크](http://127.0.0.1:3000/kiosk)를 여세요. 연결되지 않은 기기는 [기기 페어링](http://127.0.0.1:3000/kiosk/pair)에서 관리자가 발급한 코드를 입력합니다.

1. 개인정보 안내와 선택적 사진 처리에 동의합니다.
2. 피부 타입, 관심 항목, 제외 성분을 선택합니다.
3. 사진 단계에 들어가면 카메라가 자동으로 켜집니다. 처음에는 브라우저의 카메라 권한 요청을 허용하세요. 한 명의 얼굴이 중앙에 안정적으로 잡히면 **3초 카운트다운 후 자동 촬영·분석**합니다. 얼굴이 벗어나면 카운트다운을 취소합니다. **Pause camera**로 멈추거나 **Choose a photo**로 파일을 선택할 수 있습니다.
4. 자동 촬영한 사진은 비공개 로컬 분석 서비스로 전달됩니다. 직접 선택한 파일은 미리보기를 확인한 후 **Analyze my photo**를 누릅니다. **Continue without a photo**는 설문 기반 성분 추천만 실행합니다. 선택적인 **Add an AI explanation** 동의가 있어야 외부 LLM 매칭 설명을 생성하며 사진은 LLM에 보내지 않습니다.
5. **Experimental results**에서 8개 데이터셋 코드와 성분 후보, 해당 매장에서 구매 가능한 제품을 확인합니다. 사진 코드가 추천에 쓰이면 **Photo-informed ingredient ranking**이 표시됩니다. 학습에 없던 코드 조합이면 사진 코드가 제외되었다는 안내와 함께 설문 입력만 사용합니다.
6. **Finish & clear session**으로 사진, 설문, 개별 결과를 정리합니다. 상호작용이 없으면 90초에 안내하고 120초에 초기화합니다.

제품은 자동으로 등록되지 않습니다. 관리 화면에서 전체 성분을 검토하여 제품을 게시하고, 해당 매장 판매 설정에서 표시 여부와 재고를 설정해야 합니다. 승인된 매장 성분 정책과 겹치는 모델 후보가 없거나, 게시/재고/제외 성분 조건을 만족하는 제품이 없으면 추천이 비어 있는 것이 정상입니다. 초기 온보딩 정책은 여전히 예시 정책이므로 실제 운영 전 검토가 필요합니다.

## 서버 설정

새 설치에서는 `npm ci` 후 `npm run face:prepare`로 고정 버전 얼굴 위치 확인 자산을 준비하고 `npm run face:check`로 해시를 검증합니다. 현재 PC에는 준비되어 있습니다. 브라우저가 실행 중 외부 CDN에서 모델을 받지 않습니다. [라이선스·고정 버전·개인정보 경계](../public/face/NOTICE.md)를 확인하세요. 카메라는 로컬 loopback 또는 HTTPS에서 사용하세요. 실제 태블릿·미러의 권한, 방향 전환, 조명과 처리 속도는 기기에서 확인해야 합니다.

기존 `.env.local`과 `.env.supabase-admin.local`을 덮어쓰지 마세요. 키나 비밀번호를 채팅에 보내지 않습니다. 아래 값은 웹 서버의 비공개 설정입니다. `NEXT_PUBLIC_` 접두사를 붙이지 마세요.

```dotenv
ANALYSIS_PROVIDER=experimental
ANALYSIS_SERVICE_URL=http://127.0.0.1:8000
ANALYSIS_API_KEY=<기존 웹/분석 서비스의 동일한 비밀 키>
ANALYSIS_PHOTO_MANIFEST=skin-all-001
ANALYSIS_PHOTO_RUN=skin-all-head-001
ANALYSIS_INGREDIENT_MANIFEST=ingredients-001
ANALYSIS_INGREDIENT_RUN=ingredients-linear-001
ANALYSIS_DEVICE=auto
```

`auto`는 사용 가능한 경우 CUDA, 그 외에는 CPU를 사용합니다. `cpu` 또는 `cuda`를 명시할 수도 있습니다. 명시한 장치나 학습 결과를 사용할 수 없으면 시작하지 않습니다. 실패를 가짜 결과로 바꾸지 않습니다.

기본적으로 개발 실행기가 무시되는 `.local/ml-workspace.json`의 `workspace_path`에서 개인 ML 폴더와 가상환경을 찾습니다. 폴더를 옮겼다면 포인터를 수정하거나 `.env.local`에 `SENMIVA_ML_WORKSPACE=<기존 개인 ML 폴더의 절대 경로>`를 지정합니다. 필요한 경우 `SENMIVA_PYTHON=<준비된 Python 실행 파일의 절대 경로>`로 실행 환경만 바꿀 수 있습니다. 실행기는 `services/analysis/src`와 `ml/src`를 함께 불러옵니다. 학습 데이터나 체크포인트를 웹 공개 폴더에 복사하지 않습니다.

처음 연결하는 PC에서는 ML 환경에 분석 API의 고정된 의존성을 설치합니다. 아래 명령은 프로젝트 폴더에서 실행하세요. 기존 ML 폴더와 학습 결과가 준비되어 있어야 합니다.

```powershell
Set-Location 'C:\Projects\AELUNE'
$kioskMlWorkspace = (Get-Content .local/ml-workspace.json -Raw | ConvertFrom-Json).workspace_path
& "$kioskMlWorkspace\.venv\Scripts\python.exe" -m pip install -r services/analysis/requirements.lock
```

원천 코드 지원 파일이 없는 새 환경에서는 다음 명령을 **한 번** 실행합니다. 이미 준비된 파일은 덮어쓰지 않으므로 현재 PC에서 같은 이름으로 반복 생성하지 마세요.

```powershell
.\scripts\ml.ps1 prepare-code-support --extracted expanded-001 --manifest ingredients-001 --name ingredients-001-source-codes-v1
```

이 명령은 추천 JSONL 9,000건과 기존 추천 매니페스트의 원천 지문을 대조하고, 보존된 TRAIN 프로필 4,824개에서 지원하는 전체 코드 조합 145개를 확인합니다. 검증 분할은 지원 근거로 사용하지 않습니다. 결과는 개인 ML 폴더의 `contracts/ingredients-001-source-codes-v1.json`에 저장되며, 재학습하거나 원본·매니페스트·가중치를 바꾸지 않습니다. 비공개 검증 근거를 포함하므로 Git이나 웹 공개 폴더에 복사하지 않습니다.

서비스는 `ANALYSIS_INGREDIENT_MANIFEST`에서 `contracts/{매니페스트명}-source-codes-v1.json` 경로를 결정하므로 추가 환경변수는 필요하지 않습니다. 파일이 없거나 원천·학습 근거 검증에 실패하면 시작을 거부합니다. 준비가 끝나면 실행하세요.

```powershell
npm.cmd run supabase:migrate
npm.cmd run supabase:check
npm.cmd run dev:connected -- --check
npm.cmd run dev:connected
```

`supabase:migrate`는 별도 운영자 파일의 권한으로 누락된 마이그레이션만 적용합니다. 데이터 초기화 명령을 사용하지 않습니다. 기존 원천 코드 연결 자체에는 DB 마이그레이션이 추가되지 않았으며, 이후 OpenAI 모드의 동의/분석 저장용 마이그레이션은 별도로 추가되었습니다. `--check`는 환경과 Auth 설정만 확인하고 서비스를 시작하지 않습니다. 실제 체크포인트와 코드 지원 파일은 experimental 서비스 시작 시 검증합니다. 이미 기존 미리보기가 실행 중이면 그 실행 터미널에서 `Ctrl+C`로 종료한 뒤 다시 시작하세요. 같은 포트에서 다른 모드의 서비스를 재사용하지 않습니다.

서비스가 시작될 때 두 모델을 한 번 불러옵니다. 이후 손님마다 다시 학습하지 않습니다. GPU 사용량과 첫 시작 시간이 증가할 수 있습니다. 별도 개인 사진 테스트 화면의 8765 포트는 기존 연구 도구이며 키오스크 연결과는 독립적입니다.

## 데이터 흐름과 보관

브라우저 내 얼굴 존재·위치 확인 → 동의/페어링을 검증하는 Next API → 비밀 키로 보호된 FastAPI → 저장된 피부/성분 모델 → 서버의 매장 정책/상품 필터 → 키오스크 순서입니다. 선택 동의가 있으면 매칭된 성분과 목표만 OpenAI에 보내 승인된 표현을 선택하게 합니다. 서버가 실제 저장된 분석을 확인하여 사진 반영/제외 여부를 설명에 붙입니다. 클라이언트가 보낸 조직 ID나 제품 추천 결과를 신뢰하지 않습니다.

사진 형식은 정지 JPEG/PNG/WebP, 파일 최대 10MiB, 가로/세로 최소 224px, 디코딩 최대 2,500만 픽셀입니다. 애니메이션, 깨진 이미지, 지원하지 않는 형식을 거부합니다. 실시간 촬영은 비율을 유지하며 긴 변을 최대 1920px로 제한합니다. 피부 모델은 학습 검증과 동일하게 중심을 잘라 처리합니다. 실시간 카메라는 별도 MediaPipe CPU 모델로 한 명의 얼굴 크기와 중앙 위치를 확인하며 신원 인식, 피부 평가나 조명/화장 품질 인증을 하지 않습니다. 파일 업로드는 이 실시간 위치 검사를 거치지 않습니다. 선명하고 정면에 가까운 사진이 필요합니다.

얼굴 위치 좌표와 검사 프레임은 브라우저 메모리에서만 사용합니다. 고정된 로컬 모델·WASM을 사용하며 상위 SDK의 외부 이용 통계 요청은 브라우저의 동일 출처 연결 정책(CSP)으로 차단합니다. 사진 단계 이탈, 일시 정지, 숨겨진 탭, 종료와 초기화는 촬영을 중단합니다. 인식기나 권한 오류 시 촬영을 강행하지 않으며 재시도/파일 선택/사진 없이 계속을 제공합니다.

사진은 요청을 처리하는 메모리에만 있으며 DB, 파일, 고객 이력, 학습 데이터로 저장하지 않습니다. 요청 본문을 로그에 남기지 않습니다. DB에는 모델 버전, 코드별 상대 출력, 성분 후보, 입력 사용 여부 및 제품 매칭 이유만 정규화된 임시 테이블로 보관합니다. 전체 분석 버전의 `:source-codes-v1`과 `visual_condition_used_source_contract_v1` 또는 `visual_condition_unseen_in_training_omitted` 표지가 입력 정책과 실제 사용 여부를 구분합니다. 코드 지원 파일의 원천 프로필 근거는 API나 DB로 보내지 않습니다. 종료/철회/기기 해제/만료 시 기존 세션 정리 경로로 삭제합니다. 관리자는 개별 사진, 설문, 분석 결과를 조회할 수 없습니다. 브라우저에서도 이미지 URL/파일 입력을 정리하고 진행 중 요청과 늦은 응답을 무효화합니다.

## 결과를 해석할 때

- 8개 항목의 `NS/S`, `P0/P1/P2`, `NVP/VP` 등은 원본 데이터셋 코드입니다. 아직 의미와 실제 키오스크 환경에서의 정확도를 검증하지 않았으므로 정상/위험/중증도 등으로 바꾸지 않습니다.
- 펼쳐 보는 상대 출력은 보정되지 않은 모델 값이며, 진단의 확률이나 신뢰도가 아닙니다.
- 성분 모델은 예제 답변에 등장한 성분 이름을 학습한 후보 생성기입니다. 성분의 임상 효능이나 개인 안전성을 검증한 모델이 아닙니다.
- 성분 모델은 피부 타입과 미백/주름 관심 항목을 지원되는 원천 범주로 매핑합니다. 사진이 있으면 8개 코드를 원천 순서의 `initial_skin_condition` **하나의 범주**로 직렬화하고 기존 정규화·해시를 그대로 사용합니다. 보존된 학습 프로필에서 확인한 조합만 추가하며, 학습에 없던 조합은 설문 입력만 사용합니다. 이는 구조 호환 정책이지 코드의 임상 해석이나 성분 필요성의 검증이 아닙니다.
- 선택한 피부 타입·고민·민감도와 제외 성분은 사진 코드로 바꾸지 않습니다. 수분/텍스처 목표는 매장 정책에, 제외 성분은 제품 필터에 사용하며 지원하지 않는 AI 입력으로 임의 변환하지 않습니다. 나이/성별/환경 정보는 수집하지 않아 일부 학습 입력이 빠집니다. 원본 사진·CSV와 추천 JSONL의 개별 연결, 코드 의미와 전체 사진→제품 경로의 정확도는 여전히 미확인입니다.
- 후보가 매장 정책을 통과하고 제품에 포함되어 있더라도 함량, 효과, 알레르기 안전성을 보장하지 않습니다. 제품 전체 표시사항을 확인해야 합니다.

독립된 실제 손님 데이터 평가, 얼굴/사진 품질 검사, 다양한 카메라/피부색 환경 검증, 성분 전문가 검토와 개인정보 운영 점검은 별도 파일럿 과제입니다. 현재 로컬 실행기는 클라우드 배포를 제공하지 않습니다. 외부 서비스에서는 HTTPS, 비공개 분석 네트워크, 공유 요청 한도, 삭제 작업 모니터링을 준비해야 합니다.

## 연결 검증
