# API형 추천 설명 설정

OpenAI Responses API와 `gpt-4.1-mini-2025-04-14`를 첫 공급자로 사용합니다. `ExplanationProvider` 인터페이스로 분리하여 향후 공급자를 교체할 수 있습니다. 자체 LLaMA 서버나 재학습은 필요하지 않습니다. 이 모델은 Responses API와 구조화 출력을 지원합니다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-4.1-mini)

## 처리 순서와 설명 범위

1. 선택적 사진 → 로컬 ConvNeXt-Tiny → 지원되는 피부 코드 조합.
2. 코드와 설문 → 로컬 성분 후보 모델.
3. 후보 → 매장 검토 규칙·등록 전성분·재고·제외 성분 확인 → 제품 최대 3개.
4. **고객이 별도로 동의했을 때만**, 확정된 제품의 매칭 근거를 OpenAI로 전달.
5. LLM이 근거 1–2개와 문장 형식을 선택하면, 서버가 확인한 사실로 짧은 영어 설명을 조립.

현재 근거는 ‘선택한 목표에 대한 매장 규칙과 등록 성분이 일치함’입니다. 검토된 과학적 효능 설명·논문 근거는 아직 없으므로 자유로운 효능·진단·안전성·사용량 설명을 생성하지 않습니다. 향후 전문가가 승인한 자료를 추가하고 평가한 후 설명 범위를 넓힙니다. 학습 예시 답변을 승인된 효능 근거로 사용하지 않습니다. 상품 순위는 기존 추천 엔진이 결정합니다.

## 준비할 것

OpenAI API 프로젝트와 API 사용이 가능한 결제 설정, 서버용 API 키를 준비하세요. [API 키 관리](https://platform.openai.com/api-keys)에서 발급하고 채팅에 보내지 마세요. 프로젝트 사용량과 예산 알림도 설정하세요.

프로젝트 폴더에서 다음 명령으로 기존 값을 덮어쓰지 않는 설정 입력란을 준비합니다.

```powershell
npm run llm:prepare
```

Git에서 제외된 `.env.local`에 직접 입력하세요. 기존 Supabase·메일 설정은 유지합니다.

```dotenv
EXPLANATION_PROVIDER=openai
OPENAI_API_KEY=여기에_발급받은_키를_직접_입력
OPENAI_EXPLANATION_MODEL=gpt-4.1-mini-2025-04-14
```

키에 `NEXT_PUBLIC_` 접두사를 붙이지 마세요. 키가 없으면 선택 동의가 표시되지 않고 기존 매칭 이유를 제공합니다. 끄려면 `EXPLANATION_PROVIDER=disabled`로 설정합니다. 지원 모델과 API 주소는 서버에서 제한합니다.

기존 설치 업데이트 시:

```powershell
npm run supabase:migrate
npm run supabase:check
```

`202610110003_api_explanations.sql`이 선택 동의·요청 상태·제품별 설명을 추가합니다. 제한된 분석 계정에 설명 저장 함수 한 개를 추가하며, 테이블 직접 쓰기나 관리자 키는 필요하지 않습니다. 이메일을 보내거나 메일 설정을 바꾸지 않습니다.

웹 서버를 종료하고 다시 시작하세요.

```powershell
npm run dev:connected
```

## 화면 확인

새 상담의 개인정보 화면에 **Add an AI explanation (optional)** 항목이 나타납니다. 기본값은 선택되지 않음입니다. 선택하지 않아도 사진 분석과 상품 추천을 이용할 수 있습니다. 기존 상담에는 동의를 자동 추가하지 않습니다.

선택 후 결과에서 제품이 먼저 표시되고 설명이 뒤에 붙습니다. 성공하면 **AI-assisted match explanation**, 실패하면 기존 매칭 이유 또는 **Why these matched**를 표시합니다. API 오류 때문에 결과가 차단되지 않습니다.

사진 단계에서는 한 명의 얼굴이 중앙에 안정적으로 잡히면 3초 후 자동 촬영·분석합니다. 얼굴 확인은 브라우저 안에서, 피부/성분 모델은 비공개 로컬 서비스에서 실행합니다. 설명에는 서버가 실제 저장된 분석을 확인하여 ‘사진 결과가 성분 순위에 반영됨’, ‘학습에 없던 코드 조합이라 사진 결과 제외’, ‘사진 없이 설문만 사용’, ‘시연’ 중 해당 근거를 로컬에서 덧붙입니다. 이 근거 문장과 사진/코드를 OpenAI에 추가 전송하지 않습니다. 코드의 임상 의미가 확인되기 전에는 LLM이 코드로 피부 상태나 효능을 추측하지 않습니다. API가 실패해도 같은 근거와 기존 매칭 이유를 제공합니다.

## 개인정보와 비용

- 전송: 요청별 `P1` 제품 참조·`R1` 근거 참조, 매칭된 표준 성분명과 선택 목표 라벨.
- 미전송: 사진, 얼굴 코드·확률, 설문 전체, 민감성·제외 성분, 이름·이메일, 고객·매장·기기·상담 ID, 제품명·가격, AI-Hub 원본과 학습 기록.
- 선택 동의 버전은 `2026-10-openai-explanation-v1`이며 기존 분석 동의와 분리됩니다.
- API에 `store:false`를 사용하고 대화 기록·도구·파일·웹 검색은 사용하지 않습니다. 외부 보관이 전혀 없다는 뜻은 아닙니다. 기본 악용 모니터링 로그는 최대 30일 보관될 수 있습니다. [공식 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)
- 최종 설명만 정규화된 임시 테이블에 저장합니다. 종료·기기 해제·만료 정리 시 삭제되고 직원은 개별 설명을 조회하지 못합니다.
- 상담당 외부 요청 최대 한 번입니다. 원자적 DB 요청 확보로 동시 요청과 재시작 후 중복 호출을 막습니다. 실패하면 자동 재시도하지 않습니다. 요청 중 서버가 중단되면 기존 매칭 이유를 표시합니다.
- 출력 최대 512토큰, API 대기 8초, 서버 프로세스당 동시 설명 최대 4개입니다. 본문·키를 로그에 남기지 않고 사진 서비스에 OpenAI 키를 전달하지 않습니다.

공개 서비스에는 공유 사용량 제한·비용 모니터링, 고객 고지·국외 처리 검토, 공급자 계약·보관 조건, 검토된 설명 자료와 독립적인 품질 평가가 추가로 필요합니다. API 설명은 실험 모델의 정확성을 검증하거나 높이지 않습니다.

## 검증

```powershell
npx vitest run tests/explanations.test.ts tests/openai-explanation.test.ts tests/application/explanations.test.ts tests/llm-setup.test.ts
npx playwright test tests/e2e/kiosk-explanations.spec.ts
npm run test:db
```

위 자동 검증의 OpenAI 응답은 가짜이며 과금 호출을 하지 않습니다. 실제 키·모델 접근·결제 상태는 별도 확인이 필요합니다. 연결된 로컬 서버가 실행 중이면 다음 명령으로 합성 매칭 사실을 사용한 실제 요청을 명시적으로 실행할 수 있습니다. 정상 생성 시 API 사용료가 발생합니다. 고객 데이터나 메일 발송은 사용하지 않습니다.

```powershell
node scripts/experimental-db-smoke.mjs --explanation-api
```

이 검증은 별도 선택 동의, 실제 설명 생성, 추천 순위 유지, DB 저장·재조회·재요청 재사용, 종료 시 삭제와 시험 계정 정리를 확인합니다. 성공한 생성 대신 기본 이유가 반환되면 성공으로 처리하지 않습니다. 기본 테스트에는 포함되지 않습니다.

### 실제 연결 확인 결과

2026-10-11에 계정 설정 완료 후 현재 설정 파일을 다시 읽도록 연결 서버를 재시작했습니다. 합성 시험에서 실제 AI 설명 생성, 제품 순위 유지, DB 저장·재조회, 재요청 시 설명 재사용, 상담 종료 후 삭제까지 모두 통과했습니다. 고객 정보·사진·AI-Hub 원본은 OpenAI로 보내지 않았고 시험 계정도 정리했습니다. 설정 파일의 키를 바꿨다면 실행 중인 연결 서버를 반드시 재시작하세요. 기존 상담의 실패한 요청은 자동으로 다시 호출하지 않으므로 새 상담으로 확인합니다.

### 429 사용량 오류가 다시 발생한다면

키가 속한 조직·프로젝트의 [API 결제 화면](https://platform.openai.com/settings/organization/billing/overview)에서 결제 설정과 크레딧 잔액을 확인하세요. 잔액이 충분하면 해당 조직·프로젝트의 사용량·지출 한도를 확인하세요. `insufficient_quota`는 결제·한도 오류의 상위 유형이므로 잔액 부족으로만 단정할 수 없습니다. [공식 오류 설명](https://developers.openai.com/api/docs/guides/error-codes)

ChatGPT 구독료와 API 사용료는 별도입니다. [공식 결제 안내](https://help.openai.com/en/articles/9039756-managing-billing-settings-on-chatgpt-web-and-platform) 결제나 한도를 해결한 뒤 실제 검증을 다시 실행하세요. 실패한 상담은 자동으로 다시 호출하지 않으므로 화면에서는 새 상담으로 시험해야 합니다. 계정 설정이 바뀌기 전에는 반복 요청하지 마세요.
