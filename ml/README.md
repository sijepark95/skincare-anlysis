# 피부사진·성분 추천 오프라인 학습 가이드

이 학습 도구는 Next.js 웹앱, Supabase, FastAPI 분석 서비스와 별도로 실행합니다. 외부 학습 API나 서버에서 운영하는 LLM은 필요하지 않습니다. 매장 애플리케이션을 실행해도 모델 학습이 자동으로 시작되지는 않습니다.

**ConvNeXt와 ChatGPT의 사진 관찰을 비교하려면 [한국어 비교 가이드](../docs/VISION-COMPARISON.md)를 사용하세요.** 별도로 동의받은 성인 평가 사진만 사용하는 명시적인 연구 명령입니다. 학습은 계속 로컬로 수행하며, 비교의 기본 실행은 외부 전송이 꺼져 있습니다. 현재 평가 사진이 없어 실제 이미지 API 비교나 우승 모델 선택은 수행하지 않았습니다.

**본인 사진으로 테스트하려면 [9절](#9-내-사진으로-저장-모델-테스트하기)을 사용하세요.** 사진을 보관하지 않는 이 PC 전용 테스트 화면이 준비되어 있습니다.

사용자는 2026년 10월 11일 데이터의 학습 및 예정된 상업적 이용이 허용된다고 확인했습니다. 원본 이용 승인 문서는 비공개로 보관하세요.

이 PC에서는 전체 ZIP 29개의 압축 해제와 두 모델의 실제 학습·저장 모델 재평가까지 완료했습니다. 사진 모델은 정리된 학습용 1,980장과 검증용 123장으로 8개 항목을 5에포크 학습했습니다. 성분 후보 모델은 학습용 5,891건과 검증용 478건으로 54개 성분을 20에포크 학습했습니다. 원본과 기존 `head-001`은 보존했습니다. [이번 학습 결과(한국어)](../docs/ML-EXPANDED-RESULTS.md)와 [데이터 감사 결과(영문)](../docs/ML-DATA-AUDIT.md)를 참고하세요. 아래 수치는 독립 테스트나 실제 제품의 정확도가 아닌 실험용 검증 결과입니다.

제공된 데이터 구조는 AI-Hub **71886 스킨케어 성분-효능 추천 데이터**와 일치하며, 처음 제안했던 71645 피부 상태 측정 데이터와는 다릅니다. 초기 `head-001`은 중간 부위의 모공 코드 NVP/VP만 분류했습니다. 이번 `skin-all-head-001`은 상·중·하 부위를 포함해 CSV의 8개 육안 평가 코드를 분류합니다. 코드의 정확한 의미, 평가자, 사람 구분과 항목별 사진 부위 적합성은 추가 확인이 필요합니다. 수분 측정, 질환 진단이나 성분 효능 검증을 수행하는 모델이 아닙니다. 추천용 JSONL은 별도 성분 후보 학습에 사용하며, 개별 사진·CSV와의 연결을 추측하지 않습니다. 키오스크의 사진 코드 전달은 [확인된 범주 구조](../docs/ML-SOURCE-CODE-CONTRACT.md)와 보존된 학습 입력의 지원 여부를 사용하며 새로운 정답 연결이나 통합 학습을 하지 않습니다.

## 1. 현재 PC에서 학습한 모델 평가하기

**PowerShell이 어느 폴더에 있든**, 아래 전체 경로 명령으로 저장한 최선 모델을 다시 불러와 평가할 수 있습니다. 재학습하지 않습니다.

```powershell
& "C:\Projects\AELUNE\scripts\ml.ps1" evaluate-multitask --manifest skin-all-001 --run skin-all-head-001 --device cuda
& "C:\Projects\AELUNE\scripts\ml.ps1" evaluate-recommendation --manifest ingredients-001 --run ingredients-linear-001 --device cpu
```

## 2. PC 환경과 설치

확인한 환경은 RTX 4070(VRAM 약 12GB), 메모리 32GB, Python 3.12입니다. 학습용 PyTorch는 2.14.1+cu130, Torchvision은 0.29.1+cu130입니다.

학습 전용 환경과 결과의 기본 위치는 OneDrive 밖의 `%LOCALAPPDATA%\Senmiva\ml`입니다. 데스크톱 앱이 AppData를 다른 실제 폴더로 연결할 수 있으므로, 설치 스크립트는 실제 위치를 Git에서 제외되는 `.local/ml-workspace.json`에 기록합니다. 일반 PowerShell에서도 이 파일을 통해 같은 학습 폴더를 찾습니다. 다른 비공개 폴더를 명시적으로 사용하려면 `SENMIVA_ML_WORKSPACE` 환경변수를 설정할 수 있습니다.

설치 과정에서 원본 데이터는 이동하지 않습니다. 공개·공유 폴더를 피하고 본인 계정의 비공개 로컬 저장소를 사용하며, 승인 문서의 데이터 취급 조건을 지키세요. 개별 사진의 파일명·경로는 비공개 매니페스트에서 관리하고, 원본 루트 폴더는 비공개 등록 파일에 기록합니다. 이 정보는 운영 애플리케이션의 데이터베이스나 Git에 넣지 않습니다.

**현재 PC에는 이미 설치되어 있습니다.** 새 환경에서 설치하거나 기존 설치 상태를 확인할 때 실행합니다.

```powershell

```

설치 스크립트는 PyTorch 공식 배포 경로에서 버전이 고정된 CUDA 13.0용 패키지를 설치합니다. 이 사전 빌드 패키지에는 별도의 CUDA Toolkit 설치가 필요하지 않습니다. 최초 설치 시 약 2GB와 추가 의존 패키지를 다운로드합니다. 사전 학습 모델을 처음 사용할 때는 약 109MB의 ImageNet 초기 가중치를 비공개 학습 캐시에 다운로드합니다.

[PyTorch 설치 안내](https://pytorch.org/get-started/locally/)와 [ConvNeXt-Tiny 가중치·전처리 안내](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.convnext_tiny.html)를 참고하세요. 일반 이미지로 학습된 가중치이므로 ImageNet 정확도를 피부 분석 정확도로 해석하면 안 됩니다.

## 3. 데이터 등록과 짧은 시험 학습

### 새 학습 환경에서만 데이터 등록

현재 PC에는 데이터 위치와 이용 허가 확인이 이미 등록되어 있습니다. **새로 준비한 허가된 환경에서만** 아래처럼 실제 데이터 폴더를 등록하세요. 예시의 데이터 경로는 실제 위치로 바꿔야 합니다.

```powershell
.\scripts\ml.ps1 init --source "C:\path\to\approved-dataset" --training-permitted --commercial-permitted
```

허가가 확인되지 않았다면 허가 확인 옵션을 넣지 마세요. 이 옵션은 사용자의 확인 내용을 기록하며 승인 문서를 독립적으로 검증하지는 않습니다. 등록 파일에는 인증 정보를 저장하지 않으며, 이미 등록된 설정은 덮어쓰지 않습니다.

### 새 환경에서 시험용 목록 생성과 실행

아래는 처음 준비하는 환경의 절차입니다. 현재 PC의 `pores-clean-smoke`와 `smoke-001`은 이미 존재하므로 같은 이름으로 재생성·재실행하지 마세요. 다시 실험한다면 새 이름을 사용해야 합니다.

```powershell
.\scripts\ml.ps1 prepare --name pores-clean-smoke --limit 128 --cross-split-policy exclude-all
.\scripts\ml.ps1 inspect --manifest pores-clean-smoke --count 16
.\scripts\ml.ps1 train --manifest pores-clean-smoke --run smoke-001 --epochs 1 --batch-size 8 --max-steps 4 --device cuda
```

- `prepare`: 원본을 검사하고 학습·검증에 사용할 파일 목록인 **매니페스트**를 만듭니다. `--limit 128`은 각 분할의 사진 수를 최대 128장으로 제한하며, 가능한 경우 두 라벨을 모두 포함합니다.
- `inspect`: 각 분할에서 최대 16장의 이미지를 메모리에서 읽어 정상적으로 해석할 수 있는지 검사하고, 집계 결과만 저장합니다. 전체 데이터의 품질이나 인물 분리까지 검증하는 기능은 아닙니다.
- `train`: 짧은 시험 학습을 실행합니다. `--max-steps 4`는 **각 에포크의 학습 배치 수**를 최대 4개로 제한하며 검증 배치 수를 제한하지 않습니다.

### 초기 모공 실험의 데이터 정리 규칙

준비 과정에서는 원본 폴더의 CSV/JPG 쌍과 남아 있는 원천 ZIP을 직접 읽습니다. ZIP을 풀거나 추천용 JSONL을 사용하지 않습니다. 샘플을 선택하기 전에 모든 원천 쌍의 이미지 바이트를 해시로 비교하고, 같은 분할 안의 동일 사진을 정리하며, 제공기관의 학습·검증 경계를 유지합니다.

기본 설정에서는 학습·검증 사이에 동일 사진이 발견되면 중단합니다. 실제 제공 파일에서 중복이 확인되었으므로 위 예시는 `exclude-all`을 명시합니다. 이 정책은 **양쪽에 겹치는 사진의 모든 출현을 두 분할에서 모두 제외**하고 건수를 집계합니다. 원본 파일을 수정하거나 샘플을 다른 분할로 옮기지 않습니다.

별도의 비밀값을 이용해 변환한 샘플 ID는 **레코드 식별자이며, 같은 사람을 묶은 것으로 검증된 ID가 아닙니다**. 학습 중 이미지를 읽을 때도 해시를 재확인합니다. 사진 수 제한은 파이프라인 작동 확인용이며, 전체 실험에서는 정리된 전체 검증 데이터를 사용해야 합니다.

준비된 매니페스트와 실행 이름은 변경하거나 덮어쓰지 않습니다. 다른 시드나 설정에는 새 이름을 사용하세요. 준비가 실패했다고 원본을 삭제하거나 연결 규칙을 추측해 주석을 고치지 마세요. 정확히 같은 파일을 찾는 SHA-256 검사로는 비슷하게 편집된 사진이나 같은 사람의 다른 사진까지 찾아낼 수 없습니다.

## 4. 더 긴 실험 학습

현재 PC의 초기 모공 실험 `head-001`은 이미 완료되었습니다. 해당 모델은 5절의 `evaluate` 명령으로 확인합니다. 이번 8개 항목 모델은 1절의 `evaluate-multitask` 명령을 사용하세요. 새로운 모공 전용 학습을 명시적으로 진행할 때만 아래 두 번째 명령을 사용합니다. 새 학습 환경에서 처음 준비할 때는 첫 번째 명령도 필요합니다.

```powershell
.\scripts\ml.ps1 prepare --name pores-clean-full --cross-split-policy exclude-all
.\scripts\ml.ps1 train --manifest pores-clean-full --run head-002 --epochs 3 --batch-size 8 --device cuda
```

| 옵션                          | 의미                                                            |
| ----------------------------- | --------------------------------------------------------------- |
| `--manifest pores-clean-full` | 정리된 전체 실험용 파일 목록을 사용합니다.                      |
| `--run head-002`              | 새 결과 폴더 이름입니다. 기존 실행 이름은 재사용할 수 없습니다. |
| `--epochs 3`                  | 학습 데이터를 3회 순회합니다.                                   |
| `--batch-size 8`              | 학습 단계마다 사진 8장씩 처리합니다.                            |
| `--device cuda`               | NVIDIA GPU를 사용하며, CUDA를 사용할 수 없다면 중단합니다.      |

기본 학습은 사전 학습된 특징 추출부인 **백본(backbone)**의 가중치를 고정하고 평가 모드로 유지하면서, NVP/VP를 구분하는 **분류 출력층(head)**을 학습합니다. 라벨 수의 불균형을 보정하기 위해 학습 데이터의 라벨 빈도에 따라 손실 가중치를 적용합니다.

검증에는 고정된 사전 학습 전처리를 사용합니다. 이미지 증강은 제한적으로 학습 데이터에만 적용합니다. CPU를 사용하는 경우 실행 설정에 기록됩니다. 현재 Windows 구현은 데이터 로딩용 별도 작업 프로세스를 사용하지 않습니다.

백본까지 조정하는 새 미세 조정 실험에는 새 실행 이름과 `--unfreeze --learning-rate 0.00001`을 사용합니다. 이 방식은 **이전 head 체크포인트를 이어서 학습하지 않으며**, ImageNet 초기 가중치부터 다시 시작합니다.

자동 설정 탐색, 백그라운드 재시도나 운영 모델로의 자동 교체는 없습니다. `--random-init`은 합성 데이터로 작동을 확인하는 시험용이며 `--unfreeze`와 함께 사용해야 합니다. 의미 있는 기준 모델에는 사전 학습 가중치를 사용하세요. `--max-steps`를 사용한 실행은 각 에포크의 학습이 일부 배치에서 끝나는 시험이므로 전체 학습을 완료했다고 해석하면 안 됩니다.

## 5. 결과 파일과 평가

비공개 학습 폴더의 `runs/<실행 이름>`에 다음 결과를 저장합니다.

- `checkpoint-best.pt`: 검증 결과를 기준으로 선택한 모델 가중치
- `checkpoint-last.pt`: 마지막 에포크의 모델 가중치
- `run-config.json`: 실행 설정, 버전과 전처리 등 재현에 필요한 정보
- `metrics.json`: 혼동 행렬과 라벨별·전체 평가 지표

사진, 개별 설문 답변이나 원래 데이터 식별자는 결과에 넣지 않습니다. 모델 가중치도 데이터에서 파생된 비공개 자료로 취급하며, 해당 이용 허가가 허용하는 범위를 확인한 후 업로드·배포하세요. 직접 만든 신뢰할 수 있는 체크포인트를 안전한 가중치 로딩 방식으로 불러오고, 출처를 알 수 없는 pickle 체크포인트를 실행하지 마세요.

결과 폴더 위치를 확인하려면 프로젝트 폴더에서 실행합니다. 실행 이름은 확인하려는 이름으로 바꾸세요.

```powershell
$mlWorkspace = (Get-Content .local/ml-workspace.json -Raw | ConvertFrom-Json).workspace_path
Join-Path $mlWorkspace "runs\head-001"
```

**혼동 행렬, 라벨별 사진 수와 재현율, macro F1, balanced accuracy**를 함께 확인하고, 학습 데이터에서 가장 많은 라벨만 항상 예측하는 단순 기준 모델과 비교하세요. 라벨 수가 불균형하므로 일반 정확도 하나만으로 판단하면 오해할 수 있습니다.

### 저장된 모델을 다시 불러와 확인하기

```powershell
.\scripts\ml.ps1 evaluate --manifest pores-clean-full --run head-001 --device cuda
```

기본값은 `checkpoint-best.pt`입니다. 마지막 에포크 모델을 확인하려면 `--checkpoint last`를 추가합니다. GPU를 사용할 수 없는 PC에서는 `--device cpu`로 평가할 수 있습니다. GPU와 CPU의 계산 정밀도 차이로 결과가 약간 달라질 수 있으며, 학습 때 저장한 결과와의 비교가 보고서에 포함됩니다.

평가 명령은 기존 학습 설정과 매니페스트의 해시가 일치하는지 확인한 뒤, 체크포인트를 안전한 가중치 로딩 방식으로 읽습니다. ImageNet 초기 가중치를 새로 다운로드하거나 가중치를 업데이트하지 않습니다. 기존 `metrics.json`과 체크포인트는 유지하고, `runs/<실행 이름>/evaluations/<고유 평가 ID>/summary.json`에 집계 결과를 저장합니다. 원래 사진 파일명이나 개별 예측은 보고서에 넣지 않습니다.

화면의 `validation`에서 다음 항목을 확인하세요.

| 보고서 항목         | 의미                                              |
| ------------------- | ------------------------------------------------- |
| `accuracy`          | 전체 검증 사진 중 맞힌 비율                       |
| `balanced_accuracy` | NVP와 VP의 재현율을 같은 비중으로 평균한 값       |
| `macro_f1`          | 두 라벨의 정밀도와 재현율을 함께 반영한 F1의 평균 |
| `confusion_matrix`  | 실제 라벨이 행, 예측 라벨이 열이며 순서는 NVP, VP |
| `per_class`         | 라벨별 사진 수, 정밀도, 재현율과 F1               |

`head-001`의 최선 모델은 에포크 1에서 선택됐습니다. 검증 79장 중 65장을 맞혀 정확도는 **82.28%**, balanced accuracy는 **82.34%**, macro F1은 **0.8225**였습니다. 실제 NVP 39장 중 34장, 실제 VP 40장 중 31장을 맞혔습니다. 학습에서 더 많았던 VP만 항상 예측하는 기준 모델의 balanced accuracy는 50%입니다. 에포크 3은 동일한 최선 지표로 끝났으며, 동점일 때는 이전 최선 모델을 유지합니다.

제공기관의 검증 데이터는 체크포인트 선택에 사용하며 **독립 테스트 데이터가 아닙니다**. 같은 사람의 사진을 묶는 규칙, 비슷한 사진의 중복, 라벨 출처와 따로 잠근 독립 테스트 전략이 검증되기 전까지 모든 지표는 **실험 결과**입니다. 짧은 시험은 데이터 읽기, 가중치 업데이트와 모델 저장이 작동한다는 점만 확인합니다.

### 실제 매장 사진으로 시험하려면

현재 명령은 라벨이 있는 기존 검증 목록을 평가합니다. 개인 사진 한 장으로 정확도를 측정할 수는 없습니다. 초기 모공 전용 `head-001`은 키오스크에 사용하지 않습니다. 별도로 확장된 8개 출력 모델을 명시적인 실험 모드에 연결했으며 [키오스크 연결 가이드](../docs/KIOSK-MODEL-SETUP.md)에 설명했습니다. 실제 매장 환경의 정확도를 평가하려면 동의를 얻은 별도 사진에 검토된 정답을 부여하고, 같은 사람이 학습·검증 데이터와 겹치지 않는 테스트 목록을 먼저 준비해야 합니다. 이 목록은 모델이나 설정을 고르는 데 쓰지 않고 최종 평가용으로 보관합니다.

- **이미 존재하는 이름:** 준비된 목록은 재생성하지 않고, 새 실험에는 새 실행 이름을 사용합니다.

- **GPU 메모리 부족:** 다른 GPU 학습이 실행 중이지 않은지 확인하고, 새 실행 이름으로 `--batch-size 4`, 필요하면 2로 줄여 시도합니다.

## 7. 실제 키오스크 분석에 적용하기 전에

같은 사람이 학습·검증·테스트에 겹치지 않는 평가와 코드 정의 확인, 사진 품질·재촬영 기준, 예측 불확실성 보정, 실제 매장 카메라 검증, 버전이 명시된 일시적 이미지 처리 API·동의 절차, 비공개 배포와 이전 버전으로 되돌리는 절차가 추가로 필요합니다.

사용자의 명시적 요청으로 저장 모델을 메모리 전용 비공개 API와 버전이 명시된 동의 절차에 연결했습니다. 명시적인 mock 모드는 **모의 분석**, 로컬 모델 모드는 **실험용 결과**로 표시합니다. 8개 사진 코드는 원천 순서의 `initial_skin_condition` 하나의 범주로 직렬화하고, 기존 정규화·해시와 같은 학습 범주인지 확인합니다. 지원되는 조합만 설문 입력과 함께 후보 순위에 반영하며, 학습에 없던 조합은 제외했다는 안내와 함께 설문 입력만 사용합니다. 이는 코드의 임상 해석이나 성분 필요성의 검증이 아닙니다.

성분 후보는 **검토된 성분 정책 → 표준 INCI 성분명 → 해당 매장에서 추천 가능한 제품**에 매칭합니다. 선택한 피부 타입·고민·민감도와 제외 성분, 매장 범위·게시 상태·재고 필터는 사진 코드로 바꾸지 않습니다. 위 정확도·개인정보·운영 검증은 여전히 파일럿 전 과제입니다. 설정과 사용법은 [키오스크 연결 가이드](../docs/KIOSK-MODEL-SETUP.md)를 참고하세요.

### 사진 코드 지원 파일 준비

새 환경에서 실험용 키오스크를 시작하기 전에 다음 명령을 한 번 실행합니다. 현재 PC에 이미 있는 지원 파일을 같은 이름으로 다시 만들지 마세요.

```powershell
.\scripts\ml.ps1 prepare-code-support --extracted expanded-001 --manifest ingredients-001 --name ingredients-001-source-codes-v1
```

추천 JSONL 9,000건과 원래 매니페스트의 원천 지문을 대조하고, 보존된 TRAIN 프로필 4,824개를 확인해 전체 코드 조합 145개의 지원 근거를 준비합니다. 검증 분할로 지원 범주를 늘리지 않습니다. 개인 ML 폴더의 `contracts/ingredients-001-source-codes-v1.json`에 새 파일을 만들며 기존 파일·원본·가중치·매니페스트를 덮어쓰거나 재학습하지 않습니다. 프로필 검증 근거가 포함되어 있으므로 공개하거나 Git에 넣지 마세요.

운영 제공자는 `contracts/{성분 매니페스트명}-source-codes-v1.json`을 자동으로 선택하며, 추가 환경변수 없이 시작 시 검증합니다. 파일이 없거나 검증에 실패하면 시작하지 않습니다. 실제 사용 여부는 정규화된 임시 `input_coverage` 표지로 남기고 전체 분석 버전에 `:source-codes-v1`을 덧붙입니다. 원천 코드 의미와 사진·설문 연결, 사진→성분→제품 전체 경로의 정확도는 여전히 미확인입니다.

## 8. 전체 압축 자료를 이용한 확장 학습

기존 `head-001`은 모공만 예측하는 초기 실험입니다. 확장 학습은 원본 폴더 안의 ZIP 29개를 전부 풀고, 이미 풀려 있던 파일도 비공개 작업 폴더에 복사해 사용합니다. 사진 9,000장, CSV 9,000개, 추천 JSONL 9,000건과 성분 엑셀 1개를 모두 검사합니다. 압축 내부 경로·파일 크기·남은 디스크 용량·CRC를 확인하며 원본과 기존 모델을 덮어쓰지 않습니다.

사진 모델과 성분 추천 모델은 다른 학습 목표를 사용합니다.

| 모델           | 학습 입력                                              | 학습 정답                                                       |
| -------------- | ------------------------------------------------------ | --------------------------------------------------------------- |
| 피부사진 모델  | 상·중·하 부위 사진                                     | CSV의 민감성·미백·주름·여드름·모공·피부 처짐·과각질·붉어짐 코드 |
| 성분 후보 모델 | 추천 JSONL 내부의 피부 타입·상태·고민·연령대·외부 요인 | 답변에서 성분 사전으로 추출한 표준 INCI 후보                    |

사진 모델은 ConvNeXt-Tiny 특징 추출부를 공유하고 항목별 분류 출력층 8개를 사용합니다. 이번 실험에서는 ImageNet 특징 추출부를 고정하고 출력층을 학습했습니다. 비어 있거나 같은 사진에서 충돌하는 정답은 **그 항목만** 학습에서 제외하며, 다른 사용 가능한 정답은 유지합니다. 학습·검증에 겹치는 동일 사진 695개 그룹을 양쪽에서 제외하고 같은 분할의 중복을 정리해 1,980장/123장을 확보했습니다. 정리 전 9,000장을 모두 학습용으로 넣거나 검증 사진을 학습에 섞는 방식은 사용하지 않습니다.

성분 모델은 로컬에서 학습하는 다중 성분 후보 분류기입니다. 질문·답변·추론 설명·파일명·원본 ID는 입력 특징에 넣지 않습니다. 엑셀의 INCI/한글 이름을 사용해 답변에서 후보를 추출하며, 모호하거나 부정 문맥에서 언급된 이름은 제외합니다. 이 정답은 전문가가 직접 검수한 정답이 아닌 **자동 추출 정답**이므로, 평가 점수를 실제 성분 효능이나 안전성으로 해석할 수 없습니다. 답변에 없는 성분도 임상적인 부적합 정답을 뜻하지 않습니다. 학습 분할의 서로 다른 구조화 프로필 10개 이상에서 관찰된 54개 성분을 사용했습니다. 학습·검증에 겹치는 설문 식별자·동일 프로필·동일 모델 입력을 양쪽에서 제외한 후 5,891건/478건을 학습·검증에 사용했습니다. 이 건수는 사람 수가 아닙니다. 이미지와 추천 JSONL은 연결 규칙이 검증되지 않았으므로 서로 추측해 결합하지 않습니다.

다음은 새 환경에서 전체 과정을 실행하는 예시입니다. 이 PC에서 이미 만들어진 자료와 실행 이름은 재사용하지 마세요. 평가 명령만 반복할 수 있습니다.

```powershell
Set-Location -LiteralPath "C:\Projects\AELUNE"
.\scripts\ml.ps1 extract --name expanded-001
.\scripts\ml.ps1 prepare-multitask --extracted expanded-001 --name skin-all-001 --cross-split-policy exclude-all
.\scripts\ml.ps1 train-multitask --manifest skin-all-001 --run skin-all-head-001 --epochs 5 --batch-size 8 --device cuda
.\scripts\ml.ps1 evaluate-multitask --manifest skin-all-001 --run skin-all-head-001 --device cuda
.\scripts\ml.ps1 prepare-recommendation --extracted expanded-001 --name ingredients-001 --min-support 10
.\scripts\ml.ps1 train-recommendation --manifest ingredients-001 --run ingredients-linear-001 --epochs 20 --device cpu
.\scripts\ml.ps1 evaluate-recommendation --manifest ingredients-001 --run ingredients-linear-001 --device cpu
.\scripts\ml.ps1 prepare-code-support --extracted expanded-001 --manifest ingredients-001 --name ingredients-001-source-codes-v1
```

`datasets/expanded-001`에는 압축 해제 자료와 비공개 출처 기록이, `manifests`에는 모델별 학습 목록이, `runs`에는 모델별 설정·가중치·집계 결과가 저장됩니다. `contracts`에는 별도로 검증한 사진 코드 지원 파일이 저장됩니다. 모두 2절의 비공개 작업 폴더 안에 있습니다. 사진 모델 설정은 `run-config.json`, 성분 모델 설정은 `config.json`입니다. 두 모델 모두 `checkpoint-best.pt`, `checkpoint-last.pt`, `metrics.json`과 고유 평가 폴더를 저장합니다. 운영 웹앱 공개 폴더에 사진·가중치·지원 근거를 복사하지 않습니다.

확장 실험도 제공기관의 검증 분할을 모델 선택에 사용합니다. 여드름 검증은 정답이 있는 113장에 한정되며, 과각질의 드문 D 코드는 검증 4장뿐입니다. 성분 검증에는 54개 중 52개 후보만 등장합니다. 사람 분리, 라벨 정의, 근접 중복과 실제 매장 사진 평가가 추가로 필요합니다. 성분 후보는 운영 적용 전에 검토된 성분 정책과 사용자의 제외 성분 조건을 통과해야 합니다. 이번 작업은 두 개의 별도 모델 학습이며 LLM 학습이나 사진에서 성분까지 이어지는 통합 모델 학습은 포함하지 않습니다.

## 9. 내 사진으로 저장 모델 테스트하기

이 기능은 운영 키오스크와 별도로 실행하는 **이 PC 전용 연구 화면**입니다. 현재 모델 `skin-all-head-001`의 저장된 최선 체크포인트를 불러와 본인 사진의 8개 코드 예측을 확인합니다. 재학습하거나 기존 모델·평가 파일을 바꾸지 않습니다.

PowerShell이 어느 폴더에 있든 아래 명령을 실행하세요. 모델을 불러올 때 잠시 기다린 뒤 준비 완료 주소가 표시됩니다. 이미 같은 테스트가 실행 중이면 주소만 여세요.

```powershell
& "C:\Projects\AELUNE\scripts\ml.ps1" photo-test --manifest skin-all-001 --run skin-all-head-001 --device cuda --port 8765
```

1. 브라우저에서 `http://127.0.0.1:8765`를 엽니다. `localhost` 대신 이 주소를 그대로 사용하세요.
2. **사진 선택**을 누르고 본인 사진 또는 사용 허가를 받은 사진 한 장을 고릅니다. JPG·PNG·정지 WebP, 최대 10MiB, 가로·세로 각각 224픽셀 이상, 총 2,500만 픽셀 이하를 지원합니다. HEIC는 먼저 JPG로 변환하세요.
3. 얼굴 한 명이 중앙에 크게 보이는지, **중앙 자르기 예시**에 피부 부위가 충분히 포함되는지 확인합니다. 밝은 조명에서 필터 없이 촬영한 사진이나 얼굴 부위만 잘라낸 사진으로 시작하세요. 예시는 실제 서버 전처리와 조금 다를 수 있습니다.
4. 처리 동의를 체크하고 **모델로 테스트**를 누릅니다. 사진은 이때에만 이 PC의 모델로 전송됩니다.
5. 항목별 예측 코드를 보고, **코드별 출력 비중**을 펼쳐 다른 코드의 모델 출력도 확인합니다.
6. **사진과 결과 비우기**를 누르면 화면의 사진·결과·동의가 초기화됩니다. 사진 변경, 처리 중 동의 철회, 페이지 이탈과 2분 무조작 때도 이전 내용이 정리됩니다.

사진·결과를 서버 파일이나 데이터베이스에 저장하지 않으며, 사진 경로·파일명·본문·개별 예측을 로그에 남기지 않습니다. 브라우저 저장소와 외부 API·분석 도구도 사용하지 않습니다. 원본 파일은 그대로 유지합니다. 메모리 처리 후 참조를 정리하는 방식이며 보안 메모리 소거를 보장하는 기능은 아닙니다. 개인정보가 포함된 사진을 선택한 상태에서 별도로 스크린샷이나 화면 녹화를 만들지 마세요.

**결과 해석:** P0/P1/P2, NVP/VP 등은 원본 학습 코드입니다. 코드의 의미·평가 기준을 아직 확인하지 못했으므로 정상/위험·심각도로 임의 변환하지 않습니다. 출력 비중은 보정되지 않은 softmax 값이며 정답률이나 의학적 신뢰도가 아닙니다. 본인 사진 한 장에는 검수된 정답이 없으므로 이 기능으로 모델 정확도를 측정할 수는 없습니다. 얼굴·흐림·피부 영역을 자동 판정하지 않으며, 중앙 자르기와 학습 사진의 눈 가림·구도 차이로 결과가 부정확할 수 있습니다.

이 별도 연구 화면은 **피부사진 모델만** 사용하며 성분 후보·매장 제품 추천·Supabase·운영 FastAPI에 연결하지 않습니다. 키오스크에는 별도의 명시적 실험 모드 연결이 추가되어 두 저장 모델과 매장 제품 매칭을 사용할 수 있습니다. 이 연구 화면을 실행하는 것만으로 키오스크 모드가 바뀌지는 않습니다. [키오스크 연결 가이드](../docs/KIOSK-MODEL-SETUP.md)를 참고하세요.

테스트를 종료하려면 실행 중인 PowerShell에서 `Ctrl+C`를 누르세요. GPU를 사용할 수 없는 환경에서는 위 명령의 `--device cuda`를 `--device cpu`로 바꿉니다. 포트가 사용 중이라면 기존 테스트를 종료하거나 `--port 8766`처럼 다른 포트를 지정하고 표시된 주소로 접속하세요. 테스트 화면은 항상 `127.0.0.1`에만 연결됩니다.

### 사진 테스트 기능의 자동 검사

6절의 전체 Python 테스트에 사진 디코딩·체크포인트 추론·HTTP 보안 경계 검사가 포함됩니다. 추가로 프로젝트 폴더에서 아래 명령을 실행하면 실제 사진이나 학습 모델 없이 합성 이미지로 브라우저 동작을 검사합니다. 기존 웹앱의 Node 개발 의존성이 필요합니다.

```powershell
npx playwright test --config ml/tests/browser/playwright.config.mjs
```

브라우저 검사는 동의 전 업로드 없음, 8개 출력, 오류·재시도, 비우기·동의 철회·페이지 이탈·무조작 초기화, 늦은 응답 무시, 사진 디코딩 중 정리, 키보드·접근성·좁은 화면을 확인합니다. 테스트 전용 포트는 8876입니다. 기존 학습 환경 포인터가 없는 환경에서는 `SENMIVA_TEST_PYTHON`에 사용할 Python 실행 파일 경로를 지정할 수 있습니다. 브라우저 테스트의 모델 출력은 합성 값이며 실제 피부 성능 평가가 아닙니다.
